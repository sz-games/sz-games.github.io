## 1. Single Source of Truth for Game Metadata

**Problem:** Game metadata is duplicated in multiple places:
- `games.js` — a large JavaScript array with all games.
- `index.html` — a hardcoded set of game card HTML elements in `#games`.
- Several pages like `FNF.html`, `Bitlife.html`, `Slope.html` have their own hardcoded game cards.

This means adding, removing, or renaming a game requires editing multiple files independently, which is error-prone and creates data drift.

**Recommendation:** Choose one canonical source of truth — either the JS array **or** the HTML in `index.html` — and derive the other from it. The most maintainable path here is to make `games.js` the single source of truth and have the homepage (and other listing pages) render cards from it at runtime. Until a build step is introduced, add a simple validation script (or CI check) that asserts the two sources are in sync whenever a change is committed.

## 2. Remove Hardcoded API Keys and Advertising IDs From Source Control

**Problem:** Sensitive identifiers are committed directly into the repository:
- Google AdSense client ID (`ca-pub-3723218062742398`) in `index.html`
- Google Analytics ID (`G-C78TXR0XFK`) in `index.html`
- GPT ad unit paths (`/22921845643/...`, `/147246189,...`) in `index.html` and `games/game.html`

These should not be in plain text in source control. A single leak or accidental fork propagates them.

**Recommendation:**
- Move all IDs into environment-variable-driven HTML at deploy time (GitHub Actions + Secrets → rendered HTML in the `gh-pages` workflow).
- For local development, read from untracked `local-config.js` or `.env` files listed in `.gitignore`.
- Audit the repo for any other secrets (discord invite links are intentional but should still be tracked in a central config file, not duplicated across 10 files).

## 3. Security: `beforeunload` and Popstate Abuse

**Problem:** In `games/game.html` (and similar iframe-loading pages), the code uses:
- `window.addEventListener('beforeunload', ...)` to block navigation.
- `history.pushState` inside a `popstate` handler to forcefully prevent the back button from working.

This is an aggressive anti-pattern. It traps users inside game frames, interferes with the browser's native navigation model, and is a poor experience. It also does not actually achieve meaningful cloaking (modern schools and extensions detect iframe context, not navigation patterns).

**Recommendation:** Remove or significantly soften these handlers. If the goal is to discourage accidental page closure while gaming, use a single, polite `beforeunload` prompt — not a looped popstate trap. Consider adding a visible "Back to Home" button and letting the back button function normally.

## 4. Massive Global Stylesheet with Inline Styles Everywhere

**Status:** ✅ Done (2026-07-30)
**Problem:** `index.html` contained dozens of inline `style` attribute blocks, especially in the 4 Featured Game Cards section. Each card duplicated the same badge gradient, text positioning, title, cover-image filter, and fire-icon styles — worst-case for maintainability since any cosmetic change required editing ten separate `style=""` strings.

**Fix applied:**
- Added 5 semantic CSS classes to `styles.css`:
  - `.featgameit` — layout override for featured cards (flex sizing per-card).
  - `.feat-pop-badge` — gradient badge box.
  - `.feat-pop-text` — badge label vertically centred.
  - `.feat-pop-icon` — fire icon positioning inside badge.
  - `.feat-title` — game title placement.
  - `.feat-cover` — cover-image filter and sizing.
- Replaced all inline `style` attributes inside the 4 Featured card `<a>` blocks with the above class names. Inline styles on the `.featgameit` wrapper are retained as a layout-safety net because `.featgameit` in `styles.css` still carries `float: left` and `top: 50%/translateY(-50%)` from its historical use; removing them would require a further layout refactor.

## 5. Inconsistent and Typo-Ridden Category System

**Status:** ✅ Done (2026-07-30)
**Problem:** The `category` attribute / `categories` array had several concrete issues:
- `games.js` used `"Driving"` while much of `index.html` was split between `"Driving"`, `"Driver"`, and `"Casual Driver"` — so the same domain had three different spellings floating around, making the filter unreliable.
- A visible label typo: `id: 'Geomerty Dash'` in `games.js` (should be "Geometry Dash").
- Inconsistent casing for Moto X3M variant IDs (`'moto x3m 2'`, `'moto x3m pool party'`, etc.) vs. `'Moto X3M'`.

**Fix applied:**
- Normalised all category values to the correct standard spelling `"Driving"` across both `games.js` (35 occurrences) and `index.html` (35 occurrences). Every variant (`"Driver"`, `"Casual Driver"`, `"Driving"`) is now consistently `"Driving"` / `"Casual Driving"`.
- Updated the filter dropdown label in `index.html` (`data-eleven`, `data-txt` for `option-11`) to read `"Driving"` so it matches exactly.
- Fixed `id: 'Geomerty Dash'` → `id: 'Geometry Dash'` in `games.js`.
- Normalised Moto X3M variant IDs to CamelCase in `games.js`: `'moto x3m 2'` → `'Moto X3M 2'`, `'moto x3m pool party'` → `'Moto X3M Pool Party'`, `'moto x3m spooky land'` → `'Moto X3M Spooky Land'`, `'moto x3m winter'` → `'Moto X3M Winter'`, and `'moto x3m'` → `'Moto X3M'`.

## 6. Zap the Dead Code and Unreachable Paths

**Problem:** Multiple files contain unused or unreachable code:
- `script.js` — loaded nowhere by the current homepage path; `games.js` is referenced from the old `beforeop.html` and some game pages, but the canonical homepage uses `scripts.js`. Both legacy scripts accumulate entropy.
- `usingLoad` flag in `scripts.js` (lines 289–294) is declared but has an empty body.
- `loadGame()` in `scripts.js` is also empty.
- `GETIMG()` at the bottom of `scripts.js` is defined but never referenced anywhere.
- `GobalSettings.js` — name suggests a global settings module but it's loaded as a synchronous `<script>` inline in many pages. Its content loads but no callers are visible in the reviewed files.

**Recommendation:** Schedule a cleanup sweep: remove or document every unused function. A dead-code detection tool (e.g., ESLint `no-unused-vars`) would surface most of these. Add a short TODO comment where a stub is intentionally reserved.

## 7. PWA / Service Worker Stale Cache Risk

**Problem:** `service-worker.js` uses a hardcoded cache name `SzGames-1` and only precaches `/Offline.html`. The `fetch` handler uses a **NetworkFirst** strategy for images and cache-first for everything else. While images use network-first, the precache list is essentially empty for a site that serves hundreds of static assets.

**Recommendation:**
- Generate the precache manifest from a build step using `workbox-build`.
- If sticking to the static approach, at least add a `cache busting` strategy: append a content hash or version query param to JS/CSS/HTML URLs so users don't stay on stale assets indefinitely.
- Consider adding a "skip waiting" + "clients claim" pattern so updates propagate immediately on reload.

## 8. Accessibility & SEO Gaps

**Problem:** While search engine discoverability was clearly considered (crawlable cards in `index.html`, structured data), there are gaps:
- Multiple `<img>` tags lack `alt` text — e.g., many cover images inside `games/game.html` use background-image divs without `alt` semantics.
- The search input lacks an explicit `<label for="SearchBox">` (placeholder is not an accessible name).
- The game iframe lacks a `title` attribute, which is a WCAG 2.1 AA failure.
- Tab cloaking (`beforeop.html`) modifies `document.title` — this breaks accessibility tree accuracy and should be opt-in only.
- The site uses `onclick` inline handlers extensively, making keyboard-equivalent behavior uncertain in many places.

**Recommendation:**
- Add `title` attributes to all iframes embedding external content.
- Replace inline `onclick` handlers with `addEventListener` and visible/`aria` labels.
- Use `<label>` elements for form controls.
- Audit contrast ratios on hover states — several grey-on-dark UI elements may fall below WCAG AA.

## 9. External Dependency Bloat & Third-Party Risk

**Problem:** The homepage loads **5** third-party scripts synchronously or async-blocking:
- Sentry/Plausible analytics
- Google Ads (`adsbygoogle.js`, `gpt.js`)
- Google Tag Manager (GTM)
- Google Analytics (`gtag.js`)
- FontAwesome
- Material Icons (two loads — one `rel="preload"` + one `<link>`)
- `inview.min.js` from `stpd.cloud`

Each adds parsing/compile time and broadens the trust surface. `stpd.cloud/inview.min.js` is an unverified CDN with no obvious provenance — a supply-chain risk.

**Recommendation:**
- Replace `inview.min.js` with a small inline intersection-obsent polyfill or native `IntersectionObserver` (modern browsers support it well).
- Audit if all three analytics tools are truly needed — they duplicate work and add latency.
- Use `font-display: swap` and consider self-hosting icon fonts.
- Add `integrity` (SRI) hashes or move to a self-hosted copy of all third-party libraries.

## 10. Mobile Responsiveness Inconsistencies

**Problem:**
- `index.html` uses `#TopMenu` position: fixed with `right: 300px` for desktop, but the mobile breakpoint behavior is mostly handled through `display: none` rather than a redesigned layout.
- `games/game.html` sidebar is hidden under `< 1279px` which is a specific desktop-tablet breakpoint, leaving large phones (e.g., iPhone 14 Pro Max at 430px width, but scaled) with undefined behavior.
- Mobile detection uses a regex on `navigator.userAgent` — this is fragile and fails on tablets and new device classes (iPadOS now reports as desktop Safari).

**Recommendation:**
- Drop user-agent-based mobile detection entirely. Use CSS `@media` breakpoints for layout changes and JavaScript feature/width detection (if absolutely needed).
- Add viewport-tested breakpoints at `768px`, `1024px`, and `1200px+` consistently across all pages.
- Consider a reduced-ads or distraction-free mode on mobile where the top leaderboard ad is hidden to improve above-the-fold space.

## 11. Ad Policy and User Experience Conflicts

**Problem:** The site uses three ad formats on the homepage alone (leaderboard, interstitial, bottom anchor) and also "triggered" interstitials on game load. Combined with the `beforeunload` anti-pattern, this pushes toward a hostile UX: ads-splash → game-load → back-button trap → interstitial reload ad.

**Recommendation:**
- Audit the actual CPM revenue vs. bounce rate to see if interstitials are net-positive for the site. Aggressive interstitials often drive users away.
- Ensure all ad containers have sensible fallbacks (currently `<div id="...">` with no fallback text if GPT fails to fill).
- Consider lazy-loading ads below the fold, not just the ones above.

## 12. Image and Asset Path Inconsistencies

**Problem:** Cover/thubmnail paths mix several systems without a clear convention:
- Local relative paths: `./brawl-stars.jpg`
- Blob URLs across `sz-games`, `storage3`, `Games7`, `Games10`, etc. — each repo used as its own CDN.
- Inline `data:image/png;base64,` in `games.js` for `bloxd.io`.
- Inline `background-image: url(...)` covers in `games/game.html` that reference files not obviously tracked in git.

**Recommendation:**
- Standardize on local paths under `cover/` where ownership is clear, and use reproducible external URLs for third-party content.
- Add a CI check or simple Node script that crawls all `.html`/`.js` files and reports any image URLs that return 404. This prevents "dead cover" cards.
- Store only critical branding images at the repo root; move reusable assets into well-named directories.

## 14. Testing and Type Safety

**Problem:** There is a `testing/` directory with `main.js`, but no visible test runner configuration, no `package.json`, and no CI workflow. The site runs entirely without type checking or linting.

**Recommendation:**
- Add a minimal `package.json` with dev dependencies:
  - `eslint` + an HTML/CSS/JS-oriented config (or migrate to ESLint flat config).
  - `vitest` or `jest` for the few logic-heavy files (`scripts.js`, `games/game.html` logic).
- Add a basic GitHub Actions workflow that runs lint + test on every PR.
- Even one regression test for `Search()` and `filterByCategory()` would catch category-name mismatches before they ship.

---

## 15. Code Organization: CM-side Page Patterns Should Be Reusable

**Problem:** Every game page (e.g., `Slope.html`, `Bitlife.html`, `FNF.html`) duplicaes the same boilerplate: Google Analytics, Plausible, Adsense config, GTM, Ruffle, FontAwesome links.

**Recommendation:** Create a tiny static layout template or a server-side include for the shared `<head>` block. If the site stays 100% static, at minimum:
- Extract the shared `<head>` fragment into a single file (e.g., `_shared-head.html`) and duplicate-maintain it via script or CI substitution.
- Move to a minimal static site generator (e.g., 11ty) if the number of pages grows — it would eliminate all this duplication without needing a complex build.
